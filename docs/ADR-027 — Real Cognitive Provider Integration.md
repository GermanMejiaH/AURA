# ADR-027: Real Cognitive Provider Integration & Natural Conversational Intelligence

- **Status**: ACCEPTED & IMPLEMENTED
- **Date**: 2026-08-20
- **Context**: AURA 1.6 Stage 20 implemented a multi-turn, context-aware, persistent conversational runtime using rule-based/heuristic intent detection. Stage 21 transforms this runtime to utilize real LLM Cognitive Providers (specifically Google Gemini via `GeminiLLMProvider`) to interpret natural language turns, resolve conversational context, and propose tool calls.
- **Decision**:
  1. **Cognitive Contract**: Define `CognitiveTurnInterpretation`, `ToolCallProposal`, and `CognitiveMode` (`TOOL_PROPOSAL`, `DIRECT_RESPONSE`, `CLARIFICATION_REQUIRED`, `UNSUPPORTED`, `PROVIDER_ERROR`).
  2. **Zero Executive Authority**: LLM cognitive providers act exclusively as untrusted cognitive proposal generators. LLMs have zero direct tool execution authority.
  3. **Strict Validation Pipeline**: All proposals pass through `ToolRegistry.validate_parameters(tool_name, **arguments)` before being dispatched to Stage 16 `RuntimeOrchestrator`. Unknown tools or malformed arguments are safely rejected before execution.
  4. **Governed Closed-Loop Dispatch**: Proposals are executed strictly via `RuntimeOrchestrator.execute_closed_loop(...)`, preserving Stage 10 Governance, Stage 11 Policy, Stage 12 Execution Engine, Stage 13 Experience, Stage 14 Adaptation, and Stage 15 SAFE_MODE Assurance rules.
  5. **Grounded Natural Responses**: Natural responses generated by LLM or fallback formatters are strictly grounded in authoritative `ExecutionResult` outputs returned by Stage 16.
- **Consequences**:
  - LLM hallucinations cannot trigger unauthorized system actions.
  - Absence of LLM API key gracefully falls back to deterministic rule resolution without breaking runtime stability.
  - Thread-safe, persistent multi-turn conversations survive restarts while remaining fully governed.
